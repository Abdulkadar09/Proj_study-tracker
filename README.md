# Study Time Tracker

A minimal study tracker that records:
- what subject was studied
- when it was studied
- how long it lasted

## Setup

1. Install dependencies:

```bash
npm run install-all
```

2. Run the app in development:

```bash
npm run dev
```

3. Open it locally in your browser:

- `http://localhost:5173` for the React frontend
- `http://localhost:3001` for the API server

## Production deployment

The app is built to run as a single Node service. The frontend is compiled into `client/dist`, and the Express server serves it from there.

### Run in production mode locally

```bash
npm start
```

Then open:

- `http://localhost:3001`

### Share with friends on the same network

1. Run `npm start`.
2. Get your machine IP address, for example `192.168.1.20`.
3. Make sure port `3001` is open in your firewall.
4. Share this URL:

```text
http://192.168.1.20:3001
```

### Temporary internet access with ngrok

If you want friends to access it over the internet without hosting it remotely:

```bash
npx ngrok http 3001
```

Then share the public URL generated by ngrok.

## Remote deployment

This repo is ready for deployment to any Node hosting provider.

Recommended hosts:
- Render
- Railway
- Fly.io
- Heroku

### Deployment steps

1. Push the repository to GitHub.
2. Connect the repo to your host provider.
3. Configure the start command:

```bash
npm start
```

4. Make sure the hosting service sets `PORT` automatically.

### Environment configuration

The app uses Supabase Auth and PostgreSQL for public, per-user data.

Required server environment variables:

- `DATABASE_URL` - Supabase PostgreSQL connection string
- `SUPABASE_URL` - Supabase project URL
- `SUPABASE_ANON_KEY` - Supabase anon/public key

Required frontend build-time environment variables:

- `VITE_SUPABASE_URL` - same Supabase project URL
- `VITE_SUPABASE_ANON_KEY` - same Supabase anon/public key
- `VITE_API_BASE` - API base URL

For same-origin deployments, leave `VITE_API_BASE` empty. For separate backend hosting, set it to your API URL.

Render must have the Supabase values set before it builds the app because `VITE_` variables are baked into the frontend bundle.

## Notes

- `client/.env.development` is configured for local dev (`http://localhost:3001`).
- `client/.env.production` keeps `VITE_API_BASE` blank so the production frontend calls the same origin by default.
- The server already supports `process.env.PORT` for hosted environments.

## Project structure

- `client/` - React + Vite frontend
- `server/` - Express backend with PostgreSQL
